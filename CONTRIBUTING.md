# Contributing to Kirelay

Thank you for helping improve Kirelay. These guidelines apply when a repository does not provide its own contribution instructions. Follow the target repository's README and project-specific guidance for setup, supported environments, and validation.

## Report a bug or suggest a change

Search existing issues first. For a bug, include the affected version or commit, environment, steps to reproduce, expected behavior, and actual behavior. Share a minimal example using sample content. For a feature, explain the writing or development problem and the outcome you need.

Remove credentials, private writing, personal information, and production configuration from examples, logs, and screenshots. Do not disclose security vulnerabilities in public issues; use the affected repository's published private reporting channel if one is available.

## Prepare a pull request

- Keep the change focused and explain the problem it solves.
- Preserve existing user data and unrelated work. Call out migrations, changes to backup formats, API or IPC contracts, and new dependencies.
- Run checks appropriate to the change using the target repository's instructions. Report the commands and actual results, including skipped or unavailable checks.
- Include screenshots for visible interface changes and describe relevant accessibility checks.
- Update affected documentation. Distinguish implemented behavior from plans and verified behavior from assumptions.

Use concise English commit subjects; follow the target repository's existing convention. Keep product-specific build and test commands in that repository rather than copying them into these shared guidelines.

Repository visibility does not establish a license. Check the target repository's license and dependency requirements before reusing or contributing third-party material.
